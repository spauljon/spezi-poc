# android/ — Android capture app (M26: skeleton on synthetic data) and the M24 probe

Follow the root [CLAUDE.md](../CLAUDE.md) (data rules, milestone workflow, FHIR rules) and [docs/planning/android-brief.md](../docs/planning/android-brief.md). The data rules apply here without exception: the only real data is the developer's own Health Connect data, it never appears in the repo, logs, screenshots, commit messages or conversation, and only counts and field names may be reported. Synthetic data only in fixtures, tests and logs.

## Modules
- `:app` is the application (`com.aboutobjects.healthgate`): the M26 skeleton. Compose UI, OIDC sign-in, a Keystore token store, the contract-driven mapper, a synthetic source, a SQLite queue and the upload. It reads no Health Connect data yet (M27).
- `:probe` is the M24 measuring tool (`com.aboutobjects.healthgate.probe`). Kept until M28's background test, then retired.

## Stack
- Android Gradle Plugin 9.5.1, Kotlin 2.2.10, Gradle 9.6.0 (the wrapper), compileSdk and targetSdk 36, minSdk 31, bytecode target Java 17. Android Studio's upgrade assistant moved the project from AGP 8.13.0 / Kotlin 2.1.21 / Gradle 8.13 on 2026-11-11, and the developer chose to keep it (Studio re-prompts if it is rolled back). Builds pass on JDK 17.0.6, 21.0.2 and Studio's bundled 25.0.4. Command-line builds set `JAVA_HOME` explicitly (`scripts/android-test.sh` does), never the machine default. No toolchain-resolver plugin (foojay): JDKs are the ones installed locally. SpeziKt is **not** used (M24: no-go).
- Studio generated compatibility flags in `gradle.properties` (`android.builtInKotlin=false`, `android.newDsl=false` and others) so the old DSL keeps working; do not remove them without a build.
- Packages (approved 2026-11-12 for M26, pinned in `gradle/libs.versions.toml`): Jetpack Compose (BOM, Material 3, activity-compose, lifecycle-viewmodel-compose and lifecycle-runtime-compose), AppAuth-Android, OkHttp, kotlinx-serialization-json and kotlinx-coroutines (android and test), AndroidX test runner and JUnit extension. **Room and WorkManager were not approved** (the queue is plain `SQLiteOpenHelper`; background sync is M28). Any other package needs the developer's approval.

## Rules
- The contract is `app/src/main/assets/metrics.json`, a byte-identical copy of `contract/metrics.json` made by `contract/sync.sh` (`RegistryTest` and `contract/check.py` both fail if it differs). The app reads it and never hand-copies a code, unit or category. Changing mapping behaviour means changing `contract/metrics.json` and `contract/golden/generate.py` (the independent implementation) first, then `contract/sync.sh`; a mapper change that needs a different golden means one of the two implementations is wrong: find out which.
- The Kotlin mapper (`mapping/`) is tested against every golden fixture the iOS mapper is (`GoldenMappingTest`, `GoldenOtherTest`). The Health Connect fixtures (`contract/golden/healthconnect-*.json`) are for M27's record mapper.
- Quality flags are set in one place, `QualityFlagger`, applied before a sample enters the queue; never in a source or the mapper. A flag never drops or alters a value.
- The synthetic generator is a pure function of (config, window, issued): no clock, no global randomness, no state; `SyntheticGeneratorTest` scans its source for both (with a control). It injects no faults.
- Tokens: only in the Android Keystore through `KeystoreTokenStore` (AES-256-GCM, writes are synchronous because a rotated refresh token must be on disk before it is used); never logged, never in plain preferences, never in a URL or body. `TokenSet.toString` is redacted: keep it. `TokenClaims` is unverified and for display only; never authorize on it. All AppAuth use stays inside `AppAuthClient`. The packages `auth/` and `sync/` contain no logging at all (tests scan for it, with a control); a new log call there needs the developer's approval.
- A queue behaviour is specified once in `src/sharedTest` (`SampleQueueContract`) and run against the in-memory fake (JVM) and the SQLite queue (device): change both implementations and the contract together.
- A negative check needs a positive control (root rule): every refusal test here has the accepted case beside it.
- The sync engine is a port of iOS's without retraction (M27). A batch the server refuses is halved until the bad sample is alone; a 401 is retried once with a fresh token; a 403 blocks; a 5xx or no network backs off and keeps the samples.
- Debug builds trust the local POC CA (its public certificate, copied from `~/.poc-ca/ca.crt` or `$POC_TLS_DIR` at build time into a generated resource; never committed, never in release builds). The build fails with the fix if the file is missing. For the browser sign-in the phone itself must trust the CA (install `ca.crt` as a CA certificate in Settings): a browser does not use an app's network security configuration.
- The server address is `healthgate.host` (Gradle property, default `macpro16.local`), TLS only: `ServerConfiguration` refuses a non-https address.
- The probe (`:probe`) reads Health Connect with read permissions only and keeps structure only: `RecordSummary` has no field for a value, a food name or a title, and `ProbeSourceTest` pins the field list and scans for logging. A new field there, or a new log call, needs the developer's approval and a test change in the same commit.

## Build and test
- `make test-android` (JVM unit tests of both modules, no device), `make test-android-device` (SQLite queue and Keystore on a connected phone or a running emulator), `make test-android-live` (uploads a synthetic window to the live stack as `android-user`; needs the stack up). All three fail if no test ran.
- Manual: `cd android && JAVA_HOME=$(/usr/libexec/java_home -v 21) ./gradlew :app:assembleDebug`. Device: `adb` from `~/Library/Android/sdk/platform-tools`, USB debugging, Auto Blocker off. After a UI change, look at a real screen (a screenshot from the emulator or phone, synthetic data only), not just the tests.
- Commit prefix: `android:`
