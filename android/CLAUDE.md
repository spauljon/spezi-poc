# android/ — Android capture app (M30: real data under its own patient), the M24 probe and the M27 test writer

Follow the root [CLAUDE.md](../CLAUDE.md) (data rules, milestone workflow, FHIR rules) and [docs/planning/android-brief.md](../docs/planning/android-brief.md). The data rules apply here without exception: the only real data is the developer's own Health Connect data, it never appears in the repo, logs, screenshots, commit messages or conversation, and only counts and field names may be reported. Synthetic data only in fixtures, tests and logs.

## Modules
- `:app` is the application (`com.aboutobjects.healthgate`): the M26 skeleton. Compose UI, OIDC sign-in, a Keystore token store, the contract-driven mapper, a synthetic source, a SQLite queue and the upload. Since M27 it reads Health Connect (read permissions only) through `ingest/healthconnect/` and sends edits and deletions as updates and deletes (decision A11).
- `:writer` is the M27 test tool (`com.aboutobjects.healthgate.writer`): it WRITES synthetic Health Connect records (and changes and deletes only its own) so the app can be tested with no wearable. Write permissions only, no network, no reads; `WriterSourceTest` scans for that. Never ship it.
- `:probe` is the M24 measuring tool (`com.aboutobjects.healthgate.probe`). Its job (M24's measurements) is done; kept for reference.

## Stack

Android Studio's upgrade assistant moved the project from AGP 8.13.0 / Kotlin 2.1.21 / Gradle 8.13 on 2026-11-11, and the developer chose to keep it (Studio re-prompts if it is rolled back). No toolchain-resolver plugin (foojay): JDKs are the ones installed locally. SpeziKt is **not** used (M24: no-go).
- Studio generated compatibility flags in `gradle.properties` (`android.builtInKotlin=false`, `android.newDsl=false` and others) so the old DSL keeps working; do not remove them without a build.
- Packages (approved 2026-11-12 for M26, pinned in `gradle/libs.versions.toml`): Jetpack Compose (BOM, Material 3, activity-compose, lifecycle-viewmodel-compose and lifecycle-runtime-compose), AppAuth-Android, OkHttp, kotlinx-serialization-json and kotlinx-coroutines (android and test), AndroidX test runner and JUnit extension, and (M27, decided in M24) the Health Connect client `connect-client` 1.1.0. WorkManager `work-runtime-ktx` 2.10.1 was approved on 2026-11-17 for M28 (the scheduled sync). **Room was not approved** (the queue is plain `SQLiteOpenHelper`). Any other package needs the developer's approval.

## Rules
- The contract is `app/src/main/assets/metrics.json`, a byte-identical copy of `contract/metrics.json` made by `contract/sync.sh` (`RegistryTest` and `contract/check.py` both fail if it differs). The app reads it and never hand-copies a code, unit or category. Changing mapping behaviour means changing `contract/metrics.json` and `contract/golden/generate.py` (the independent implementation) first, then `contract/sync.sh`; a mapper change that needs a different golden means one of the two implementations is wrong: find out which.
- The Kotlin mapper (`mapping/`) is tested against every golden fixture the iOS mapper is (`GoldenMappingTest`, `GoldenOtherTest`). The Health Connect fixtures (`contract/golden/healthconnect-*.json`) are for M27's record mapper.
- Quality flags are set in one place, `QualityFlagger`, applied before a sample enters the queue; never in a source or the mapper. A flag never drops or alters a value.
- The synthetic generator is a pure function of (config, window, issued): no clock, no global randomness, no state; `SyntheticGeneratorTest` scans its source for both (with a control). It injects no faults.
- Tokens: only in the Android Keystore through `KeystoreTokenStore` (AES-256-GCM, writes are synchronous because a rotated refresh token must be on disk before it is used); never logged, never in plain preferences, never in a URL or body. `TokenSet.toString` is redacted: keep it. `TokenClaims` is unverified and for display only; never authorize on it. All AppAuth use stays inside `AppAuthClient`. The packages `auth/` and `sync/` contain no logging at all (tests scan for it, with a control); a new log call there needs the developer's approval.
- A queue behaviour is specified once in `src/sharedTest` (`SampleQueueContract`) and run against the in-memory fake (JVM) and the SQLite queue (device): change both implementations and the contract together.
- A negative check needs a positive control (root rule): every refusal test here has the accepted case beside it.
- The sync engine is a port of iOS's without retraction (M27). A batch the server refuses is halved until the bad sample is alone; a 401 is retried once with a fresh token; a 403 blocks; a 5xx or no network backs off and keeps the samples.
- Debug builds trust the local POC CA (its public certificate, copied from `~/.poc-ca/ca.crt` or `$POC_TLS_DIR` at build time into a generated resource; never committed, never in release builds). The build fails with the fix if the file is missing. For the browser sign-in the phone itself must trust the CA (install `ca.crt` as a CA certificate in Settings): a browser does not use an app's network security configuration.
- The server address is `healthgate.host` (Gradle property, default `macpro16.local`), TLS only: `ServerConfiguration` refuses a non-https address.
- Health Connect (M27): everything that touches a record is in `ingest/healthconnect/`: the pure `HealthConnectMapper` (no clock, no Android class, tested against `contract/golden/healthconnect-*.json`), the `HealthConnectGateway` interface (the real one wraps the client; tests use a fake), and `HealthConnectCollector`. The package has no logging and no write call (`HealthConnectSourceTest`, with controls); the app declares READ permissions only (the six record types, and since M28 reading in the background). The collector's rules (token after commit, last change wins, window then changes, nutrition by content) are in its class comment and in `HealthConnectScenarioTest`: change them together.
- The queue's rules for update, delete and redelivery are one pure object, `QueueRules`, used by every implementation; `SampleQueueContract` runs on the fake (JVM) and SQLite (device). A change to a rule changes the object, the contract and both.
- The unit accessors of the Health Connect library are `inKilocalories`, `inGrams`, `inMilligrams`, `inMilliliters` (Java getters have other names), stage names come from `HealthConnectAccess.stageNames` (the library's own map uses different names), and `HydrationRecord` needs start before end.
- Background sync (M28): everything that syncs goes through `SyncRunner` (the buttons, a sign-in and `SyncWorker`, which WorkManager runs every 15 minutes with a network). The runner honours the pause switch (`PauseStore`, kept across a kill), reads even while signed out (the queue holds the samples; a sign-in runs the runner and they go up), and never overlaps itself. `SyncWorker` asks WorkManager to retry only for a temporary problem (`RunResult.worthRetrying`); a block that needs the user ends the run quietly with a line in the attempt history (`AttemptStore`, kept across a kill; words and counts only). The app declares `READ_HEALTH_DATA_IN_BACKGROUND` (read-only) and asks for it where `HealthConnectAccess.backgroundReadSupported`.
- Failpoints (`debug/Failpoints`) are named places in the sync path where a test can stop the process: the debug source set has the real object and a receiver/provider for `adb`, the **release source set has an empty twin and no receiver**. Never call anything from `src/debug` outside `Failpoints.hit`. The unit tests throw `SimulatedProcessDeath` (an `Error`, which no `catch (e: Exception)` swallows); `scripts/android-process-death-test.sh` kills the real process. A new place where a crash could lose data gets a failpoint and a test in `BackgroundSyncTest`.
- WorkManager does not run a periodic job early even when the system forces it (`cmd jobscheduler run -f` says "executed before schedule"): test the worker with the debug `ENQUEUE_WORKER` action and the schedule with `SyncSchedulingTest`.
- Patient routing (M30, the Android counterpart of iOS's per-source patient): every `IngestItem` has a `PatientRoute`. A Health Connect record written by the `:writer` test tool (`TestOrigins`) and every synthetic sample is `TEST` (patient `poc-android-01`); any other app's record is `REAL` (patient `poc-real-android`, Gradle property `healthgate.realPatient`). **Fail closed:** with no real patient configured the real samples are HELD in the queue (`SyncStatus.held`, shown on the screen) and never filed under the test patient; the engine sends one transaction per patient, never a mixed one. A sample on the server under the wrong patient is moved by a delete and a create (`RowAction.Refile`): when the routing rules change, raise `HealthConnectCollector.ROUTING_EPOCH` and every phone reads its window once more after the upgrade. Tests plant three bugs (fail open, route ignored, no refile) and each is caught (`PatientRoutingTest`, `SampleQueueContract`).
- The app's own sources never log or print (`NoLoggingOfSamplesTest`); the debug-only code logs only counts and words, never a sample, record or value. Never put a sample in a log, a toast, a screenshot or a dump.
- Accessibility (M30): every button is at least 48 dp tall, section titles are headings, the pause control is one labelled switch. `scripts/android-a11y-check.sh` reads the real screen's accessibility tree over adb (controls named, targets 48 dp); colour contrast, focus order and TalkBack's wording need a person (see the runbook).
- The probe (`:probe`) reads Health Connect with read permissions only and keeps structure only: `RecordSummary` has no field for a value, a food name or a title, and `ProbeSourceTest` pins the field list and scans for logging. A new field there, or a new log call, needs the developer's approval and a test change in the same commit.

## Build and test
- `make test-android` (JVM unit tests of both modules, no device), `make test-android-device` (SQLite queue and Keystore on a connected phone or a running emulator), `make test-android-live` (uploads a synthetic window to the live stack as `android-user`; needs the stack up). All three fail if no test ran.
- Process-death and memory: `scripts/android-process-death-test.sh collector|engine` and `scripts/android-peak-memory.sh` (debug builds; see docs/runbooks/android-device.md).
- Phone: the Health Connect tests need the writer (`:writer:installDebug`) and `python3 scripts/android-hc-counts.py` (counts only). Install with `ANDROID_SERIAL=<serial>` when an emulator is also connected, and run the device tests (`--device`) on the emulator, not the phone (the test run uninstalls the app, which would wipe its sign-in and queue).
- Manual: `cd android && JAVA_HOME=$(/usr/libexec/java_home -v 21) ./gradlew :app:assembleDebug`. Device: `adb` from `~/Library/Android/sdk/platform-tools`, USB debugging, Auto Blocker off. After a UI change, look at a real screen (a screenshot from the emulator or phone, synthetic data only), not just the tests.
- Commit prefix: `android:`
